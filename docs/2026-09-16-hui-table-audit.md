## 1. 关键结论：哪些列旧版**从来不显示**

平开表的闸门变量 `he`（`:948`）与移门表的 `ge`（`:3906`）都是 `Vue.ref(!1)`，
**全组件（含模板）没有任何赋值点**（已对格式化文件与原始打包产物各扫一遍，
`expose` 里也只有 `ping_hui`/`diao_hui`/`selectAll`/`unselectAll`，不碰它们）。

⇒ **日期、回执单号、图片ID、客户、客户编号、其它费用 六列在旧版汇算页从不渲染**，
是这份构建里的死代码（移门表那两列「客户」同样不渲染）。

新版处理：这些列**保留但默认隐藏**（仍可在「列显隐设置」里打开）——比旧版多一个开关，
不会丢信息。其余默认值取自该厂真实配置（见 §3）。

## 2. 逐格：标签文字与结构

旧版的**每个小标签都是 `div.glass-input-label`**，样式
`font-size:11px; white-space:nowrap; color:#1302fa; min-width:0`（**蓝色 11px**），
且**文案一律带全角冒号**。我们原来用的是灰色 10px、无冒号、还缩写过（面/底/厚），
逐格对完如下（括号内是绑定的行字段，**标签名 ≠ 字段名的地方加粗**）：

### 平开表

| 列 | 行（自上而下） |
|---|---|
| 型材/颜色 | `型材：`(型材) · `颜色：`(颜色) |
| 单价/数量 | `单价：`(单价) · `数量：`(数量) |
| 玻璃 | `门玻：`/`面玻：`(面玻,按 diamond 分支) · `固玻：`/`底玻：`(底玻) · `厚度：`(**玻璃厚**，不分支) |
| 开向 | `包边：`(**套线种类**) · `锁具：`(**轨道种类**) · `开向：`(开向) · 开向示意图 |
| 门洞尺寸 | `高度：`(门洞高) · `左宽：`/`宽度：`(门洞宽) · ` 母门宽: `(**轨道长**) · `门宽：`/`墙厚：`(墙厚) · `右宽：`(**亮窗总高**) · `洞/净尺：`(洞尺) |
| 备注 | `地址：`(**安装地址**) · `备注：`(备注, **textarea**) |
| 金额 | `金额：`(只读) · `平方数：`(只读，右键改) |

|---|---|

### 已改的三处结构差异

1. **「洞尺」不是独立列** —— 旧版两张表里它都是**门洞尺寸格里的最后一行**
   （平开 `:2336-2346` 两项「洞尺/净尺」；移门 `:5128-5141` 四项「洞尺/净尺/单包洞尺/双包洞尺」）。
   我们原来做成了独立列，且平开表错用了四项取值集。**已并回门洞尺寸格，取值集按表分开**。
2. **门洞尺寸的行序**：旧版 `高度：` 在上、`宽度：` 在下（决定先后顺序的那个三元
   `l.value`/`g.value` 也是恒 false 的死代码），我们原来平开是「高→宽」正确但把洞尺单列了，
   移门则多塞了「母门宽」。**已按旧版重排，移门去掉母门宽**。
3. **备注是 textarea**（`el-input type="textarea" :autosize="{minRows:1}"`），不是单行输入框。
   **已改**。

### 语义细节（已改）

* **开向示意图要先把「自定义开向名」还原成原始开向再查表** ——
  旧版是 `ve.value[C(开向)]`，`C` = `getOriginalOpenDirection`。我们原来直接用 `l.direction` 查，
  用户给开向起过自定义名就会掉图。**已改成 `PING_DIRECTION_IMAGES[getOriginalOpenDirection(...)]`**。
* **五金是多选**，行字段存**下划线分隔串**（`a_b_c`），候选里去掉已选，
  下方再渲染一行 `join("、")`。我们原来是单选。**已改成多选 + 明细行**。
* **金额恒只读**：`readonly:!we["金额"][id]`，而 `we` 只在 onBlur 里被写成 `false`
  （`!false` 仍是 true）⇒ 永远不会变可编辑。**已做成只读输入框**（原来是自绘的 `¥ x.xx` span）。
* **数字类输入红字**（`.red-number-input .el-input__inner{color:red}`）只挂在：
  平开 `门洞高/门洞宽/墙厚/钻石「右宽」`；移门 `门洞高/门洞宽/墙厚/封板高`。
  **独立的「亮窗总高」列不红**，吊脚/轨道长/边封数也不红。**已按此上色**。

## 4. 开向示意图：我们那份映射错了一半

旧版开向图不是一张表，是**两张**，按租户配置的 `锁向` 二选一：

```js
ve = computed(() => _["value"]["锁向"] === 1 ? J : Q)   // Hui.formatted.js:950
img.src = ve.value[C(行["开向"])]                        // :2219
```

而图上画的是谁，由 `f()`（`:629`）反查得出：

```
_0x489d6c = swingDoorRight      （右内开）
_0x5d4c6f = swingDoorLeft       （左内开）
_0x31486f = swingDoorOuterRight （右外开）
_0x4abd6f = swingDoorOuterLeft  （左外开）
```

线上租户的 `ping_column.锁向 = 1` ⇒ 走 **J**，即「长名短名都直配」：
`左锁内开/内左 → 左内开`、`右锁内开/内右 → 右内开`、`左锁外开/外左 → 左外开`、`右锁外开/外右 → 右外开`。

`app/src/data/directionImages.ts` 里那份 **8 个「X锁X开」全对，4 个短名（内左/内右/外左/外右）全反**
（短名错配成了 Q 的口径）。**已交换修正，现 14 项与旧版 J 逐项一致。**

> 该文件头写着「勿手改」，但这次是按旧版常量 + 线上配置**定量核对后**改的，
> 不是凭感觉调 —— 核对脚本的判据是 base64 与 `1_right-a00c7e0a.js` 里 `a/y/n/i/B/p` 六个常量逐字相等。

## 5. 有意的偏离（**不是** bug，别再"修"回去）

| 项 | 旧版 | 新版 | 理由 |
|---|---|---|---|
| 移门第 25 列表头 | 也叫「客户」（重复） | `客户编号`(client_code) | 旧版笔误，行模型里本就有 `客户编号` |
| 单双丁的存储 | 平开借用 `边封数`（数值 1/0/3/4/5/2），移门用 `单双丁`（字符串） | 两表统一用 `double_ding`（字符串）+ 独立 `edge_seal_count` | 旧版两个编码混用；新版自有数据模型，**界面选项与标签完全一致** |
| 母门宽绑定 | `e["轨道长"]`（标签叫母门宽、存的却是轨道长字段，`onInput` 校验又按"门洞宽"） | 独立字段 `mother_door_width` | 旧版是字段复用；新版分开更清楚，且 `dimsOf` 的 `s` 正取这个字段 |
| 日期/回执单号/图片ID/客户/客户编号/其它费用 | 恒不渲染（死代码） | 默认隐藏、可开 | 保留能力 |
| 批量删除 / 隐藏按钮 | 无 | 有 | 我们自己的便利入口 |
| **「点击传图」不加名字字幕带** | 选文件 + 填门图名字 → 在照片下方拼一条**白底红字**字幕带（88px，按 measureText 换行）再存 | 只弹系统文件框、原图直接存 IndexedDB | **用户 2026-09-16 拍板：不做，现在这样挺好** |

## 6. 还没做的（记下来，别当成已完成）

- **金额/打折的 `readonly` 开关**：旧版 `we` 只写 `false`，实际恒只读，已照做；
  但它显然本意是「首次失焦后解锁可改」——旧版这条是坏的。要不要在新版做成**真能手动改金额**，
  待业务确认（同 `自定义方数` 那次）。
- **`锁向` 设置**：新版没有这个概念，开向图直接按 J（该厂的值）写死。
  若将来要支持 `锁向=0` 的租户，需要把 Q 表也带上并按配置切换。
- **`el-autocomplete` vs 我们的 `NSelect`**：旧版型材/颜色/开向/轨道/套线/玻璃/封板高/计价方式
  都是 el-autocomplete（可自由输入 + 候选）。我们多数已开 `tag`（可输入新值），
  但**计价方式**仍是纯下拉（旧版可自由输入）。影响很小，未改。
- **打折**：旧版是 `el-input`（且 onFocus 会先清空再 select），我们用 `NInputNumber`。
- **列宽**：旧版是内容测宽出的 `min-width`（初值 40–70，玻璃/上轨边封 `+10`），
  我们是写死 px + 表格 `scroll-x`。观感接近，未逐列对齐。
