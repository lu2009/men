# 新版电子回执单（2026-09-17）

> 旧版三个组件（`ReceiptView` 已登录 / `ReceiptShare` 无认证 / `ReceiptMobile` 卡片）全部逆向完成，
> 新版按同一分工实现。本文记录**旧版语义**与**新版落地**，以及每一处有意偏离。

## 1. 旧版架构

| 文件 | 路由 | 认证 | 职责 |
|----|----|----|----|
| `ReceiptMobile-2bb0962e.js` | — | — | 卡片渲染器（两张页面共用），`export {ve as _}` |
| `ReceiptView-2e239d4a.js` | `/receipt-view/:receiptNo` | 要 | 取数 + 渲染 |
| `ReceiptShare-48082842.js` | `/receipt-share` | 不要 | 取数 + 渲染，自带一份**旧版**行构造器 |
| `receiptBuilder-76e5b538.js` | — | — | `export {gs as a, ps as b}`：`ps` 回执行数组 / `gs` 客户信息 |

深链（Home「电子回执单」按钮产出）：

```
https://www.samrtdoor.com.cn/login?param1={客户名}&param2={token}&receiptNo={回执单号}
token = `{i}af{c}wy{Date.now()+888}`    i = ds==="smartdoor" ? 1000 : Number(ds.split("smartdoor")[1])+1000
                                        c = 7 * 客户编号 + 1987
```
校验侧 `token.split("wy")`，**7 天**窗口。该 token 依赖旧系统自己的用户库，新版没有那套表，故**不复刻**。

`ReceiptShare` 里的行构造器是 `ps` 的**更早版本**，两处差异（以 `ps` 为准）：
尺寸标签（新版 ` 亮窗` vs 旧版 `亮高`）、方计价取整位（旧版 2 位、新版 3 位）。

## 2. 旧版行格式化（`ps`，已逐 token 解码确认）

反混淆：`legacy/js/receiptBuilder-76e5b538.js` 的字符串表用单字母函数名，通用解码器解不了，
需专用脚本（同 `Home.formatted.js` 的套路）。关键 token：`287="<br>门玻:"` `289="固玻:"`
`324="无玻璃"` `333="底玻:"` `352="单玻:"` `304="平方数"` `294="加价项目"` `342/345="折价:"`
`288="扇数:"` `295/317="轨道种类"` `319/341="套线种类"` `353=" 口袋门"` `323=" 只做门套"`。

数组顺序：**先全部平开（`ping_hui`）、再全部吊趟（`diao_hui`）**，各自保持原序（无排序）。

| 列 | 平开 | 吊趟 |
|----|----|----|
| 开向 `direction` | `套线种类 + 原始开向`（**不是**自定义显示名） | 原始开向 |
| 开向图 `openImg` | `PING_DIRECTION_IMAGES[getOriginalOpenDirection(开向)]` | `DIRECTION_IMAGES[扇数+开向] \|\| DIRECTION_IMAGES[开向]` |
| 玻璃 | 单玻 → 无玻璃 → 钻石（`固玻:x<br>门玻:y*Tmm`）→ `底玻:x<br>面玻:y*Tmm` | 同左，无「背板」支 |
| 尺寸 | 钻石 `高H左宽W[门宽亮窗][右宽墙厚]`／子母 `高H宽W母门轨道长[*亮高][*墙厚][*吊脚]`／普通 `高H宽W[亮高][*墙厚][吊脚]` | `高H宽W[ 亮窗][ 亮窗数:][ 墙厚:][ 轨道长:]` |
| 计价 | `•单价元/套*数量=` / `•单价元/方*平方数=`，**不含套线**；再追加 `加价项目`（`<br>•` 分隔） | 同左，**含套线**（长度恒用 `(2×max(高,亮窗)+宽+2×增量)/1000`）；再追加加价项目 |
| 备注 | `[折价:X折][安装地址][备注]` | `[折价:X折][扇数:N][轨道种类:X][套线种类:X][安装地址][备注]`，扇数按型材含「哑口」→` 只做门套`、含「+0」→` 口袋门` |
| 价格 `price` | 单价 > 0 取单价，否则 `'/'`（卡片据此隐藏「单价:」） | 同左 |

标题 `profile` 走 `innerHTML`（旧版就是 `innerHTML` 渲染型材名，保留）。

### 客户信息（`gs`）
`client / tel / date / productionDays / orderNo / lastDay / total / deposit / 订单备注 / address /
balance / 门数 / 安装地址 / declaration / payQrcode`。
`total = round2(Σ金额)`、`门数 = Σ数量`、`balance = round2(Σ金额 − 定金)`。

### 卡片（`ReceiptMobile`）
客户卡（订单详情 / 单号 / 客户 / 下单日期 / 安装地址）→ 门项目明细（共 N 项）→
每张门卡（开向图、型材、开向/颜色/玻璃/尺寸、数量 ×N、查看图片、单价、金额、
可展开的 计价说明/备注/生产进度）→ 费用汇总（门数 N 套 / 合计金额 / 已付款 / 待付款）→
订单须知 → 支付二维码 → 页脚「电子回执单 · 安全可信」。

**费用汇总的覆盖**：卡片先取 `customerInfo`，若财务接口拿到数据，
则 `已付款 = 已分配金额`、`待付款 = 未收金额`（`finance_getOrderFinanceSummary`）。

## 3. 新版落地

### 后端（`backend/src/modules/receipts`）

| 方法 | 路由 | 认证 | 说明 |
|----|----|----|----|
| GET | `/api/v1/receipts/{receipt_no}` | 要 | 回执载荷 |
| POST | `/api/v1/receipts/{receipt_no}/share` | 要 | 签发分享令牌 |
| GET | `/api/v1/public/receipts?no=&t=` | 不要 | 凭令牌取回执载荷 |

分享令牌：`{tenant_id}.{exp_epoch}.{hex(HMAC-SHA256(secret, "{tenant_id}.{exp}.{receipt_no}"))}`
（`core/receipt_token.rs`，HMAC 手写、不引依赖）。7 天有效；**单号不放进令牌**，
换单号复用同一令牌会验签失败。密钥 `RECEIPT_SECRET`（生产必设）。

服务端**只下发原始数据**，回执行由前端现算 —— 旧版就是前端构造的（开向图、自定义开向命名、
加价项目文本都依赖前端资源）。`declaration` 恒为 `含安装费`（旧版 `租户.declaration || "含安装费"`，
新版 tenants 表暂无该列）。

### 前端

- `utils/receiptBuilder.ts` —— `buildReceiptPicture`（`ps`）/ `buildReceiptCustomerInfo`（`gs`）
- `components/ReceiptCard.vue` —— `ReceiptMobile`，样式逐条照抄 `legacy/css/ReceiptMobile-4bd5d8bb.css`
- `views/ReceiptView.vue` → `/receipt-view/:receiptNo`（要登录，可复制分享链接）
- `views/ReceiptShare.vue` → `/receipt-share?no=&t=`（无认证）
- `views/Home.vue` 行操作列新增「电子回执单」
- `utils/markupLines.ts` —— 加价项目文本，从 `Hui.vue` **抽出**、与打印回执共用同一份

## 4. 有意偏离（逐条核实过，不是漏抄）

| # | 偏离 | 原因 |
|----|----|----|
| 1 | 分享链接不再是旧域名深链，改为本系统 `HMAC` 签名令牌 | 旧 token 依赖旧系统用户库，新版无此表 |
| 2 | 首页按钮进**预览页**，分享链接在预览页一键复制（旧版直接复制） | 旧版看不到内容、剪贴板失败也无提示；新版多一步但两件事都能干 |
| 3 | `/receipt-view` 右上角 ✕ 回订单页（旧版跳 `/terminal-orders`） | 新版没有终端订单页 |
| 4 | 无「查看3D」按钮 | 新版没有 three.js 3D 模块，留着点了没反应 |
| 5 | 无「支付二维码」卡片 | 旧版收款码取自旧服务端图片库；新版只在各人本地 IndexedDB，**分享页读不到分享者的浏览器**，需租户级收款码设置（未做） |
| 6 | `productionDays` 取库里的 `production_days`，不用 `ceil((截止日期−日期)/天)` | 新版 `due_date = order_date + 生产天数 + 1` 是**推导**出来的，照抄公式会恒比真实值大 1 |
| 7 | `total`/`门数` 取订单头落库值，不遍历 `ping_hui`/`diao_hui` 现加 | 同口径（Σ金额 / Σ数量），避免两处漂移 |
| 8 | 展开箭头挪进 `.door-main` | 旧版 DOM 上它是 `.door-card` 的兄弟，而 `position:absolute` 找不到定位祖先（`.door-card` 无 `position`），箭头会飘到整页右侧中部 |
| 9 | 平开开向用**原始名**（不套自定义命名） | 旧版电子回执就是原始名（打印回执才用 `displayDirection`）。若要与打印一致，改 `receiptBuilder.ts` 的 `direction` 一行即可 |
