### ⚠️ 第 30 条的根因

`App.vue` 的 `n-config-provider` **没传 `:locale`**，naive 默认 `enUS`；
`n-input-number` 会把 locale 的 `InputNumber.placeholder` 当默认 placeholder
（`naive-ui/es/input-number/src/InputNumber.mjs:149`），英文包写的是 **"Please Input"**。
已全局补 `:locale="zhCN"` + `:date-locale="dateZhCN"` —— **影响面不止财务页**。

## 六、数字口径

| # | 字段 | 现在是什么 |
|---|---|---|
| 43 | **客户余额** | 「**还欠多少**」，≥0。不是账户净额、不会为负 |
| 44 | **实收金额** | **累计充值**：只算客户级收款，且**逐笔减掉这一笔自己的分配**、逐笔夹零后求和；**红冲不减** |
| 45 | **未分配余额** | 客户池子里的钱（净额），可正可负 |
| 46 | 预付款分配·资金池剩余 | 「**本次没分掉的**」；「客户池子还剩多少」另显示为「资金池可用」 |
| 47 | 分配金额 | **按客户池子封顶**：池子里没钱一分也分不出去 |
| 48 | 优惠 | 记成**订单调整**，**不从客户池子扣**（店家让利） |
| 49 | 收满的单 | **没有优惠**（预付款分配时优惠恒 0；本单收款时护栏拦住并提示） |
| 50 ⭐ | **本单收款的「预计抵扣」** | = **收款额 × 比例**，与后端实记**完全一致**（见下） |
| 51 | 未收金额 | **永远不为负** |
| 52 | 删除订单红冲 | 按**来源**拆两条腿（本单收款 / 池分配分开冲） |

### ⭐ 第 50 条为什么这么定（重点）

旧版**前后端用的是两个公式**，而且两边各自都不自洽：

| | 公式 | 问题 |
|---|---|---|
| 旧版**前端**预览 | `min(未收 × 比例, 预付款可用)` | 跟「这次付多少」**无关** ⇒ **付 1 元也能拿满额优惠**，能反复薅；且按「预付款可用」封顶却**不消耗**预付款，拦不住任何东西 |
| 旧版**后端**实记 | `收款额 × 比例`（`svc:346`） | 与预览不符 |

**取后端那套**（用户拍板）：优惠是对**这一笔收款**的让利，基数就该是收款额；跟实付成正比，薅不动。
于是把前端预览改成同一个式子 —— **预览显示多少，实记就是多少**。

（若业务真要「按单免 X%」，那是一个**订单级**优惠，正解是订单抹零、类型选「优惠」，
不该挂在收款表单上 —— 它跟「收了多少」本来就没关系。）
