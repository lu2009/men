## 0. 一页结论 —— 底座能复用的只有 5 段，且 PS 不属于 C 家族

**PS 不是 C 家族的第三个成员。** §骨架 §1.2 说的「三种配置形状」在代码层比报告写的还要远：
PS 的 **CSS / HTML / 分页 / 清洗** 四块**没有一行能与 `docsheet/` 共用**，
连类名派生规则都对不上（见 §0.3）。

### 0.1 逐段判定（这就是「底座要加哪些参数」的答案）

| 底座文件 | PS 能不能用 | 判定依据 |
|---|---|---|
| `docsheet/types.ts` `PaperConfig/PrintConfig` | ⚠️ **形状可用、语义要改** | PS 的 `paper` 多一个 `globalHeaderFont`（不在 paper 里，是顶层第四块）；`print` 多一个 `itemsPerPage`；`orientation` 的**归一化方向相反**（见 §2.1 注 3） |

| `docsheet/profile.ts` `DocSheetClasses` | ❌ **派生规则不成立** | `createDocSheetClasses('ps')` 给出 `ps2-title`/`ps2-table`/`ps2-line`…，**PS 一个都不吐**（§0.3） |
| `docsheet/html.ts` `escapeHtml`（`K`） | ✅ **逐字相同，直接用** | `PS:779-784` 与 `GS:182-187` 5 条 `replace` 完全一致 |

| `docsheet/paginate.ts` `waitForImages` | ✅ **可直接用** | PS 的 `printDirect` 等图段（`PS:1412-1424`）与 `GS:493-506` 逐字同构（`complete` / `onload` / `onerror`，**无超时**） |

### 0.2 与 PS2（C 家族）的规模对比 —— 别按「改 4 处」估工

| | PS2（§diff §0） | PS（本单） |
|---|---|---|
| 与参照物的差异 | **4 处**（行来源 / 列集 / 空行语义 / 贴皮） | **没有参照物**。与 PS2 同名的只有 `ps-root`/`ps-sheet` 两个 class 和打印骨架 |
| 核心层 C SS/HTML | 前缀替换 | 全内联样式，709 字符 CSS |
| 分页 | 量测 iframe（ps2 与 gs2 逐字节同） | **解析式估高，无 iframe**，且**首页/后续页预算不同** |

全文枚举 PS 吐出的 class：`grep -o 'class="[^"]*"'` → **只有 `ps-root`（1 次）与 `ps-sheet`（5 次）**。

## 2. 配置模型（问题 2）—— B 家族与 C 家族的根本差别

### 2.1 顶层形状（`PS:33-243`，CONFIRMED）

```
{
  paper:            { widthMm, heightMm, orientation, paddingMm }
  globalHeaderFont: { fontFamily, fontSize, fontColor, fontWeight }
  headerFields:     [ 12 × HeaderField ]
  tableConfig:      { showBodyBorder, underlineBrElements, rowHeight, tableFontSize, tableTopMm, columns[4] }
  doorImgBox:       { enabled, x, y, width, height }
  print:            { copies, itemsPerPage }
}
```

**与 §骨架 §1.2 那张表的出入（以本表为准）**：骨架表把 `tableConfig` 的键写成
`{columns[],tableFontSize,rowHeight,showBodyBorder,underlineBrElements,tableTopMm}`，
**漏了 `doorImgBox` 的 5 个字段位置说明与 `globalHeaderFont` 整块**，
且没提 `print.itemsPerPage`。逐字清单如下。

**默认值**（`a()`，`PS:33-243`）：

| 块 | 字段 | 默认值 |
|---|---|---|
| `paper` | `widthMm` / `heightMm` / `orientation` / `paddingMm` | **`210` / `148` / `"portrait"` / `5`** —— **A5 纵向**（GS2/PS2 是 `297/210/landscape/3`，§diff §2.1） |
| `globalHeaderFont` | `fontFamily` / `fontSize` / `fontColor` / `fontWeight` | `"Microsoft YaHei"` / **`19`** / `"#000000"` / `"normal"` |
| `tableConfig` | `showBodyBorder` / `underlineBrElements` / `rowHeight` / `tableFontSize` / `tableTopMm` | `true` / `true` / **`37`（px！）** / **`16.5`（pt）** / **`42.5`（mm）** |
| `doorImgBox` | `enabled` / `x` / `y` / `width` / `height` | `false` / `128.5` / `80.5` / `43` / `50` |
| `print` | `copies` / `itemsPerPage` | `1` / **`1`** |

> **注 1（单位）**：`rowHeight` 是 **px**（UI 标签「表体行高(px)」16–60），渲染时一律
> `0.2646 * rowHeight` 换算成 mm（`PS:1073 / 1234 / 934`）。**与底座的 `rowHeightMm`（mm）不是一回事。**
> **注 2（tableTopMm 的哨兵）**：`-1` = 自动（= 可见字段最大 `y` + 12，见 #21）。
> `z()` 的 clamp 下界也是 **`-1`**（`PS:371-378`）。
> **注 3（orientation 的归一化方向相反）**：PS 是
> `"landscape" === v ? "landscape" : "portrait"`（`PS:298-304`，**只认 landscape**），
> 底座是 `v === 'portrait' ? 'portrait' : 'landscape'`（`sanitize.ts:60`，**只认 portrait**）。
> 两边的兜底值正好相反。**别复用底座的 `sanitizePaper`。**
> **注 4（orientation 仍是死字段）**：与底座一致 —— 无任何消费者。
> `printSilent` 用 `widthMm > heightMm` 判横向（`PS:1461`），CSS 的 `@page` 只读两个数值
> （`PS:1030`）。**只有设置弹窗的方向下拉与 `z()` 读写它。**

| # | 拖什么 | 挂在 | 处理器 | 写哪 | X clamp | Y clamp | mouseup 后 |
|---|---|---|---|---|---|---|---|

**共同点（三套逐字一致的部分）**：
- 监听方式：`mousedown` 里 `document.addEventListener("mousemove", d)` + `("mouseup", V)`；
  mouseup **只做 `removeEventListener`**（不改选中态、不刷新、不落库）。
- 位移换算：`Δclient / k`，基准是 mousedown 时的 `x/y` 快照。
- 吸附：`Math.round(2 * v) / 2` = **0.5mm**。
- 都**写布局草稿 `s`**，不写生效配置 —— ★ 与 QL 的拖拽（写生效 + 立即落 localStorage，§骨架 §2.5）**完全不同**。

**逐套的差异（逐字源码级）**：

① `j`（`PS:711-736`）：`e.preventDefault() + e.stopPropagation()` → `U("table","")` → 记 `clientY`、`T.value`、`k`；
move: `i = round2(a + (clientY-o)/k)`，clamp `[0, heightMm - paddingMm - 10]`，写 `s.value.tableConfig.tableTopMm`。

② `q`（`PS:737-767`）：`preventDefault + stopPropagation` → `U("doorImgBox","")` → 快照 `x/y`；
move: 两个方向都 `round2` 后 clamp，**直接改 `n.x` / `n.y`**（`n = s.value.doorImgBox`，引用）。

③ **字段拖拽（`PS:3957-4022`，逐字）**：

## 9. 未确认

1. **`tableTopMm < 0` 且 `headerFields` **全部不可见**时**：`oe` 里写的是
   `Math.max(...[].map(e => e.y)) + 12` —— 空数组的 `Math.max` = **`-Infinity`**，
   于是首页预算 `g = heightMm - 2P - (-Infinity) - V - 4 = +Infinity` ⇒ **永不翻页**（首页吞掉全部行）。
   而布局编辑器里的 `S` computed（`PS:613-619`）**显式处理了这个情况（返回 45）**，`oe` 里**没有**。
   ⇒ 这是旧版的一处不一致/缺陷。**未确认**：默认 12 个字段全 `visible: true`，实际触发需要用户
   逐个取消勾选 —— 是否值得照抄这个缺陷，需要拍板。（**建议：照抄**，与 `paddingMm` 的 `NaN` 缺陷处理口径一致；
   但要在注释里标出来。）
2. **`wc`（编辑生产单保存）在 `itemsPerPage=2` 时会二次配对**（**已按 §6.5 收紧，CONFIRMED**）：
   `HOME:10057` 是 `Ur.value = e`（`e` 来自 §6.5 的 `ProductionEditOld`，**形状是配对行**）
   → 再 `Sr()` 又跑一次 `sc()`。
   - **配对数 = 1 时是 no-op**：`sc` 里 `b = rows[1]` 为 `undefined` ⇒ 走 `else out.push(a)`，原样返回。
   - **配对数 ≥ 2 时真的二次配对**：`{...P1, orderID1: P2.orderID, orderID11: P2.orderID1, …}`。
     关键字段（`orderID`/`oldSheet`/`size`）**歪打正着地活着**（`te` 剥一层后缀正好还原），

   **未确认**：旧版是否真被这么用过（属于长期潜伏的脏数据源）。

   `config.print.itemsPerPage === 2` 决定 `oldSheetProduces(paired)`（§8.1 D2），

   「配置变了才重建行」，而不是「每次保存行都重建」）。
