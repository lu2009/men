## 2. 五张的共同形状

都是一样的骨架，这也是为什么收据单的实现能当模板用：

```
buildXxxHtml(数据)  →  返回 HTML 字符串给 Home  →  Home 塞进预览容器
                    →  各自的打印路径（自绘，不吃 hiprint）
```

每张的 expose 都有且仅有一个 `buildXxxHtml`：

| ic | expose 的构建方法 |
|---|---|
| 12 | `buildReceipt2Html` |
| 13 | `buildQualifiedLabelHtml` |
| 14 | `buildProductionSheetHtml` |
| 15 | `buildProductionSheet2Html` |
| 16 | `buildGlassSheet2Html` |

**每张都有自己的「未就绪」提示**，用于 ref 为 null 或方法缺失时：
`自定义生产单组件未就绪`(`dr[472]`)、`自定义合格标签组件未就绪`(`dr[1013]`)、
`自定义生产单2组件未就绪`(`dr[1070]`)、`自定义玻璃合片单组件未就绪`(`dr[799]`)、
以及收据单的 `收据单2组件未就绪`。

## 3. 差异：配置界面走两条路

| | 收据单（ic=12） | 其余四张（ic=13–16） |
|---|---|---|
| 配置入口 | `openFontDialog`（字体调节）+ 元素微调浮层 | `openLayoutEditor`（布局编辑） |
| 配置内容 | 6 类字号 / 纸张 / 显隐 / 品牌 / 10 元素几何 | 整版布局 |
| 设置弹窗标题 | `收据单2 设置` | `自定义XXX - 布局编辑` / `自定义XXX - 设置` / `自定义XXX - 打印设置` |

> ⚠️ 这也是**早先那份文档记错模型的原因**（见 `docs/2026-09-16-print-font.md` §3 的更正块）：
> 「自定义合格标签」那套 `{paper:{…,paddingMm}, globalFont:{fontFamily,…}, fields:[…]}` 模型
> 属于**合格标签**，被误记成了收据单的。**合格标签才是旧版唯一能换字体族的地方**
> —— 它的词汇表里有「字体 / 宋体 / 黑体 / 苹方 / 粗细 / 对齐 / 换行 / 行高」。

## 4. 各张的字段与特征（从字面量词汇表读出的）

### 13 自定义合格标签（`QualifiedLabelPrintManager`）

纸型小（旧文档记的 70×90 就是它）。字段：编号 / 客户 / 地址 / 型材 / 开向 / 颜色 / 玻璃 / 尺寸 / 备注。
配置项最丰富：

- 版面：纸张宽高、方向（横向/纵向）、内边距(mm)、常用尺寸
- 字体：**字体（宋体 / 黑体 / 苹方）** / 字号 / 粗细 / 对齐（左、右、居中）/ 换行 / 行高
- 自适应：「适应纸张宽度」「整体自适应」「`(宽-边距×2)`」「mm 自适应完成」
- **自动隐藏空**（空字段不占位）
- 打印：系统默认打印机 / 打印份数 / 获取打印机列表

### 14 自定义生产单（`ProductionSheetPrintManager`）

字段最全，且**带图**：单号 / 制单 / 客户 / 地址 / 型材 / 开向 / 颜色 / 玻璃 / 尺寸 /
门扇 / 外框 / **门图 / 锁图 / 二维码** / 备注。
（对比 hiprint 的生产单：这张是重排版、带图形的版本。）

### 15 自定义生产单2（`ProductionSheet2PrintManager`）

字段：单号 / 订单信息 / 门扇 / 外框 / 方向 / 门图 / 备注。**双联**（旧分析记为「双联」）。

### 16 自定义玻璃合片单（`GlassSheet2PrintManager`）

字段：单号 / 客户 / 门类 / 方向 / 门图 / 备注。

## 5. 对后续工作的意义

- **收据单的实现可直接当模板**：`utils/receipt2/` 那套（存储 → 清洗 → CSS 发生器 → HTML 构造器 →
  分页 → 打印/导出）的五段结构，其余四张可以照搬，替换各段的字段与 CSS 即可。
- **但它们共用「布局编辑器」**，而收据单走的是「字体调节 + 元素微调」——那套布局编辑器
  **还没逆向过**，是这四张的主要未知量。四张共用一个编辑器意味着**做一次可复四处**。
- 优先级建议：**玻璃合片单**（602 行）与**生产单2**（609 行）最小，可先做；
  合格标签虽然 944 行但它是旧版唯一能换字体的地方，产品价值可能最高。

## 6. 未做/未验

  （很多字符串在解码表里，未逐一解）。
- **共享的布局编辑器组件没有定位到**：`openLayoutEditor` 是各组件自己的方法（Home 只做转发），
  编辑器本体未确认是内联在各组件里还是另有共用组件。
- 代码量按 `Home.formatted.js` 的切片统计；该文件与原始 minified 的行数不可比
  （美化过），但**相互之间可比**。
