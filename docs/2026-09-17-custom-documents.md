# 旧版「自定义单据」族 盘点（2026-09-17）

> 起因：做完「自定义收据单」后要摸清**还有几张同类单据**。
> 旧版 Home 在打印选项抽屉里有一个分组 `自定义单据：`（`dr[972]`），下面全是**自绘单据**
> —— 不走 hiprint，各自手拼 HTML、自带样式、自己一套配置界面。

## 1. 全族五个组件

| ic | 界面名 | 组件名 | 代码量 | 配置方式 | 新版状态 |
|---|---|---|---|---|---|
| 12 | **自定义收据单** | `Receipt2PrintManager` | 1000 行 / 44 KB | 字体调节 + 元素微调 | ✅ **已完成** |
| 13 | 自定义合格标签 | `QualifiedLabelPrintManager` | 944 行 / 44 KB | 布局编辑 | ⬜ 未做 |
| 14 | 自定义生产单 | `ProductionSheetPrintManager` | 1189 行 / 58 KB | 布局编辑 | ⬜ 未做 |
| 15 | 自定义生产单2 | `ProductionSheet2PrintManager` | 609 行 / 28 KB | 布局编辑 | ⬜ 未做 |
| 16 | 自定义玻璃合片单 | `GlassSheet2PrintManager` | 602 行 / 27 KB | 布局编辑 | ⬜ 未做 |

合计 **4344 行 / 201 KB**；收据单那 44 KB 已完成，**剩余约 157 KB**。

**ic 的划分很干净**：1–11 是 hiprint 那 17 张模板，**12–16 就是这五张自绘单据**，一一对应。

### ⚠️ 入口数 > 组件数 —— 别把入口当成单据

抽屉里有 **24+ 个入口按钮**，但只对应 **17 张 hiprint 模板 + 5 张自绘单据**。
同一个组件会被多个入口复用，**只换喂进去的数据过滤**。

**合格标签族是最典型的**：三个入口、**同一个组件**（`QualifiedLabelPrintManager`，`fr` ref）、
**同一个 `ic=13`**：

| 入口按钮 | handler | 调用的数据方法 | ic |
|---|---|---|---|
| ` 自定义合格标签 `（`dr[1487]`） | `br` | `lable()` —— 全部 | 13 |
| ` 平开合格标签 `（`dr[720]`） | `Dr` | `lable({ping:true, diao:false})` | 13 |
| ` 推拉合格标签 `（`dr[734]`） | `Ar` | `lable({ping:false, diao:true})` | 13 |

三个 handler 的函数体**逐字相同**，唯一差别就是那行 `lable({ping, diao})`。
⇒ **新版不需要做三张单据**，做一张合格标签 + 一个入口的数据过滤参数即可。

> 同理，`平开标签` / `生产标签` / `料标签` / `标签`这几个**不是自定义族** ——
> 它们走 `ic=4` 等值，是 **hiprint 的 `lable` 模板**（已在我们导入的 17 张里）。

### 证据来源

- 入口按钮文案全在 `dr` 表：`dr[1487]`=` 自定义合格标签 `、`dr[1151]`=` 自定义生产单 `、
  `dr[1008]`=` 自定义生产单2 `、`dr[529]`=` 自定义玻璃合片单 `、`dr[1336]`=` 自定义收据单 `
- 组件名：`Receipt2PrintManager` 是字面量；其余四个是解码值
  （`Ca[272]` / `Ha[460]` / `Vn[384]` / `bn[223]`）
- ic 值：从各入口函数体里读出的 `ic.value = N`
- 代码量：按 `defineComponent` 花括号配平切片（脚本见 §4）

## 2. 五张的共同形状

都是一样的骨架，这也是为什么收据单的实现能当模板用：

```
buildXxxHtml(数据)  →  返回 HTML 字符串给 Home  →  Home 塞进预览容器
                    →  各自的打印路径（自绘，不吃 hiprint）
```

每张的 expose 都有且仅有一个 `buildXxxHtml`：

| ic | expose 的构建方法 |
|---|---|
| 12 | `buildReceipt2Html` |
| 13 | `buildQualifiedLabelHtml` |
| 14 | `buildProductionSheetHtml` |
| 15 | `buildProductionSheet2Html` |
| 16 | `buildGlassSheet2Html` |

**每张都有自己的「未就绪」提示**，用于 ref 为 null 或方法缺失时：
`自定义生产单组件未就绪`(`dr[472]`)、`自定义合格标签组件未就绪`(`dr[1013]`)、
`自定义生产单2组件未就绪`(`dr[1070]`)、`自定义玻璃合片单组件未就绪`(`dr[799]`)、
以及收据单的 `收据单2组件未就绪`。

## 3. 配置界面：**每个 ic 都有两套**，别只数一套

> ⚠️ **本节 2026-09-17 更正**：初版只写了「布局编辑器」，**漏了另一半**。
> 四张自定义单据**同时**有两个入口，改的是**完全不同的东西**：

| | A. 编辑**行数据** | B. 编辑**版式** |
|---|---|---|
| 弹窗 | Home 侧挂载，定义在 **Hui chunk**（`ProductionEdit` / `ProductionEditOld` / `LabelEdit`） | 组件自带 `openLayoutEditor` |
| 改什么 | 订单行的字段值（单号/型材/门图/备注…） | 版面：纸张、列、字号、边距 |
| 持久化 | **不持久化**（只改内存里的行数组） | 写 localStorage |

按钮对照（`ic` 激活后工具栏同时出现两颗）：

| ic | A 的按钮 | B 的按钮 |
|---|---|---|
| 13 合格标签族 | `编辑标签` | `编辑布局` |
| 14 自定义生产单 | `编辑生产单` | `编辑布局` |
| 15 自定义生产单2 | `编辑生产单` | `布局设置` |
| 16 自定义玻璃合片单 | `编辑合片单` | `布局设置` |

**收据单（ic=12）是异类**：它没有 A，B 也换了个名字叫「字体调节」（`openFontDialog`），
外加一套「元素微调」浮层。

> 三套编辑弹窗的 props/emits 签名**完全一致**（这正是它们能共用的原因），
> 但**数据形状不同**：`ProductionEdit` 是平铺行、`ProductionEditOld` 是 oldSheet 嵌套族+双联、
> `LabelEdit` 是标签行纯拷贝。⇒ 新版只需**一个**共用弹窗组件（列定义与 `brFields` 做成参数），
> 另两个的转换各留扩展点。

> ⚠️ 另：**收据单的 `openFontDialog` 与四张的 `openLayoutEditor` 不是同一套**。
> 四张的配置项以「纸张 + 打印机」为共同底（tabs 结构一致），合格标签在此外还多一套完整的
> 逐字段字体；收据单则是六类字号 + 元素微调，模型完全不同。

> ⚠️ 这也是**早先那份文档记错模型的原因**（见 `docs/2026-09-16-print-font.md` §3 的更正块）：
> 「自定义合格标签」那套 `{paper:{…,paddingMm}, globalFont:{fontFamily,…}, fields:[…]}` 模型
> 属于**合格标签**，被误记成了收据单的。**合格标签才是旧版唯一能换字体族的地方**
> —— 它的词汇表里有「字体 / 宋体 / 黑体 / 苹方 / 粗细 / 对齐 / 换行 / 行高」。

## 4. 各张的字段与特征（从字面量词汇表读出的）

### 13 自定义合格标签（`QualifiedLabelPrintManager`）

纸型小（旧文档记的 70×90 就是它）。字段：编号 / 客户 / 地址 / 型材 / 开向 / 颜色 / 玻璃 / 尺寸 / 备注。
配置项最丰富：

- 版面：纸张宽高、方向（横向/纵向）、内边距(mm)、常用尺寸
- 字体：**字体（宋体 / 黑体 / 苹方）** / 字号 / 粗细 / 对齐（左、右、居中）/ 换行 / 行高
- 自适应：「适应纸张宽度」「整体自适应」「`(宽-边距×2)`」「mm 自适应完成」
- **自动隐藏空**（空字段不占位）
- 打印：系统默认打印机 / 打印份数 / 获取打印机列表

### 14 自定义生产单（`ProductionSheetPrintManager`）

字段最全，且**带图**：单号 / 制单 / 客户 / 地址 / 型材 / 开向 / 颜色 / 玻璃 / 尺寸 /
门扇 / 外框 / **门图 / 锁图 / 二维码** / 备注。
（对比 hiprint 的生产单：这张是重排版、带图形的版本。）

### 15 自定义生产单2（`ProductionSheet2PrintManager`）

字段：单号 / 订单信息 / 门扇 / 外框 / 方向 / 门图 / 备注。**双联**（旧分析记为「双联」）。

### 16 自定义玻璃合片单（`GlassSheet2PrintManager`）

字段：单号 / 客户 / 门类 / 方向 / 门图 / 备注。

## 5. 对后续工作的意义

- **收据单的实现可直接当模板**：`utils/receipt2/` 那套（存储 → 清洗 → CSS 发生器 → HTML 构造器 →
  分页 → 打印/导出）的五段结构，其余四张可以照搬，替换各段的字段与 CSS 即可。
- **但它们共用「布局编辑器」**，而收据单走的是「字体调节 + 元素微调」——那套布局编辑器
  **还没逆向过**，是这四张的主要未知量。四张共用一个编辑器意味着**做一次可复四处**。
- 优先级建议：**玻璃合片单**（602 行）与**生产单2**（609 行）最小，可先做；
  合格标签虽然 944 行但它是旧版唯一能换字体的地方，产品价值可能最高。

## 6. 抽屉入口 → ic 全映射（穷举）

**ic 1–16 全部覆盖，无缺口。** 枚举方式是「先找所有给 `ic` 赋值的函数（入口的充要条件），
再反查各自的按钮文案」—— 比按按钮块正则扫更可靠（上一版那么扫漏了 ic 6/7/9/10）。

| ic | 入口按钮 | handler | 性质 |
|---|---|---|---|
| 1 | 玻璃合片单 | `Sc` | hiprint |
| 2 | 生产单 / 平开门生产单 / 移门生产单 | `Tc` / `Gc` / `qc` | hiprint（三入口共用） |
| 3 | 玻璃订单 | `Uc` | hiprint |
| 4 | 标签 / 平开标签 / 推拉标签 | `xc` / `kr` / `Pr` | hiprint `lable`（三入口共用） |
| 5 | 收据单 | `hi` | hiprint |
| 6 | 订单汇总 | `Ci` | **不是打印** —— 君豪汇总订单（Excel 导出） |
| 7 | 平开门生产单(定制) | `jc` | hiprint |
| 8 | 生产单定制 | `Wc` | hiprint |
| 9 | 生产单定制(竖版) | `Oc` | hiprint |
| 10 | 生产标签 | `Mc` | hiprint `product10` |
| 11 | 料标签 | `Hc` | hiprint |
| **12** | **自定义收据单** | `pi` | **自绘** ✅ |
| **13** | **自定义合格标签 / 平开合格标签 / 推拉合格标签** | `br` / `Dr` / `Ar` | **自绘（同一组件）** |
| **14** | **自定义生产单** | `gi` | **自绘** |
| **15** | **自定义生产单2** | `ti` | **自绘** |
| **16** | **自定义玻璃合片单** | `wi` | **自绘** |

**规律**：ic 1–11 是 hiprint 模板（其中 ic=2、4 各挂 3 个入口），**12–16 是五张自绘单据**。
另有少数入口 ↔ 多入口共用同一 ic，差别只在数据过滤（见 §1）。

> **`di` 也设 ic=16，但它是「直接打印」**—— 那不是入口，是 ic=16 激活后才出现的**操作按钮**。
> 旧版工具栏一共 ~24 个按钮，是**入口 + 操作**混在一起数的，别当成 24 张单据。
> 同类操作按钮还有 `ic=13` 的「手动打印 / 标签机设置 / 编辑布局」、
> `ic=16` 的「打印设置 / 手动打印 / 编辑合片单」、`ic=15` 的「布局设置」。

### 对不上的一处（如实记下）

我们导入的 hiprint 模板有 **17 张**，但抽屉里只够到 **11 个 hiprint 入口**。
差的几张应当是**从别的页面/入口使用**（Hui 等），本次没追。
`docs/2026-09-17-home-print.md` §4 记的「旧版 ~24 个入口」现可精确为：
**16 个 ic × 若干多入口 + 一批操作按钮**。
