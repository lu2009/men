## 0. 一句话结论

**旧版的加价项目不是一套逻辑，是两套。** `Ping_hui`（平开）与 `Diao_hui`（吊趟）在旧版里各写了一份
**重算函数**、**自动带出**、**候选选择**，行为都不一样；新版把它们合并成了一套共用实现。
这是本模块最大的差距来源，也是唯一会**算错钱**的地方。

## 2. P0 —— 会算错 / 少算

### 2.1 「超宽 / 超高」永远不会自动带上 ⭐

**旧版**（`Hui.formatted.js:1578-1626`，Ping `Qt`）：门洞宽 / 门洞高 / 墙厚 失焦时，从目录里挑一条
`^超(宽|高|墙厚)\d+$` 且 `unit==="元/公分"` 的项自动挂到本行，取「阈值 < 实际尺寸 且差值最小」的那条，
并先把本行同前缀的旧项清掉。

```js
// :1583  门洞宽/门洞高 仅「套」计价才自动；墙厚恒自动
if("墙厚"!==t&&"套"!==e[a(505)])return;
if(t===a(484))_="超宽"; else if("门洞高"===t)_="超高"; else { if("墙厚"!==t)return; _="超墙厚" }
```

**新版**：只有 `syncWallThicknessMarkup`（`Hui.vue:1827-1846`，仅墙厚），
**门洞宽 / 门洞高 没有任何钩子**。`recalcMarkup`（`:1519-1565`）只是在**已挂的项里**挑 winner，
不会从目录带 ⇒ 这两类项**永远不会被自动选中**。

### 2.2 平开 / 吊趟的金额分支被合并成了一套 ⭐

**旧版 Diao `ft`（`:4170-4204`）逐字读出来：**

```js
// :4179  元/方 —— 没有「超平米」特判
d = Number((e.price * t[平方数]).toFixed(3))
// :4203  元/米 —— 直接用门洞宽，压根不看名字里有没有「门套」
else e[unit]===a(303) ? (c = t[a(124)]/1e3, d = Number((e.price*c*t["数量"]).toFixed(3)), …)
// :4194  轨道超长只在吊趟这边有
else if(e[名称].includes("轨道超长")){ c = Number(替换后的数字)/10 }
```

**旧版 Ping `wt`（`:1260-1311`）**：`元/方` 有 `超平米` 特判（`:1268`）、`元/米` 有 `门套` 特判（`:1278-1279`）、
`元/公分` 分支里**没有** `轨道超长`。

| 单位 | 平开 `wt` | 吊趟 `ft` | 新版 `markupAmount` |
|---|---|---|---|
| 元/方 | 有 **超平米** 特判：`(平方数−N)` | **无**，只有 `price×平方数` | ❌ 两边都走超平米 |
| 元/米 | 有 **门套** 特判：含"门套"才算，长度 `(2×max(高,亮窗)+宽)/1000` | **完全不判门套**，长度 `门洞宽/1000` | ❌ 两边都按平开 |
| 元/公分 | 超高 / 超宽 / 超墙厚 | 多一个 **轨道超长**（`数字/10`，且 `Math.round` 取整） | ❌ 两边都带轨道超长 |
| 超宽基准 | `门洞宽` | `Math.max(门洞宽)`（对单个数取 max，原版无意义） | — |
| 无 | 数量>1 / =1 文案不同（**金额同**） | 一律 `price×数量` | 只影响明细文案 |

新版出处：`Hui.vue:1471-1512`（`markupAmount`），函数只收 `l: Line`，**没有 `line_type` 分支**。

### 2.3 没有「修改加价项目」

**旧版**：管理弹窗有 新增 / 修改 / 删除 三个入口，修改走 `param1=editPrice`，body 是
`{before:{name,price,unit}, after:{name,price,unit}}`（`:8065-8072`）；删除走 `param1=deleteAddPrice`，
body `{name,price,unit}`，带 `ElMessageBox.confirm("确定要删除此加价项目吗?")`（`:8123-8133`）。
两者成功后都 `window.location.reload()`（`:12843-12845`）。

**新版**：原先只有 `GET / POST / DELETE /api/v1/add-price-items`，**没有「修改」**。
已补：后端 `PUT /api/v1/add-price-items/{id}`（`settings/{handler,service,mod}.rs`）+
前端 `api.updateAddPriceItem`。旧版用 `{before,after}` 是因为它的服务端没有主键；
新版有 id，直接按 id 改，语义等价。
管理 UI 也按旧版拆成三弹窗：`加价项目管理`(400，两个按钮) → `新增加价项目`(500) / `修改加价项目`(500，
底部 `取消`/`删除`/`确认修改`)。

## 3. P1 —— 建档 / 兼容

### 3.1 目录没有种子

**旧版**：模块级单例，恒有 `{name:"人工", price:100, unit:"元/套"}`（`legacy/js/useAddPriceItems-937065cb.js`；
主页另有一份同种子 `Hui.formatted.js:7978-7980`）。
**新版**：`markupCatalog = ref([])` 空起步（`useMarkupCatalog.ts:17`），后端表空就是空。

### 3.2 自动加价开关的存储值格式不兼容

```js
// 旧版读（Hui.formatted.js:835 / :938）
localStorage.getItem("smartdoor_disable_auto_markup") === "true"
// 新版（Hui.vue:938 / :941）
LS.get('smartdoor_disable_auto_markup') === '1'   /   LS.set(…, v ? '1' : '0')
```

新版自洽，但**与旧版数据不兼容**：浏览器里若残留旧版的 `"true"`，新版读成 `!= '1'` ⇒ 判为「未开启」。

> **注（初稿修正）**：默认语义两边一致（未设置 = 自动加价开启），所以**只有迁移过来的浏览器**会翻转，
> 不是逻辑错。另外旧版保存时还会 `dispatchEvent(new CustomEvent("auto-markup-setting-changed"))` 做跨组件同步，
> 新版只有一个页面、不需要。

### 3.3 目录加载失败静默

**旧版**：`getAddPrice` 非 200 或解析失败 → `ElMessage.error("初始化失败")`（`:979` 已核；另在 Diao
`:3914-3921`、主页 `:8157-8167` 各有一份 `getAddPrice` 调用）。
**新版**：原先 `catch {}` 直接吞掉。已改：`loadMarkupCatalog()` 返回布尔，调用方（页面 onMounted、
「修改/删除」入口）失败时弹 `初始化失败`。
> 实现注：`useMarkupCatalog` 是模块级单例、**拿不到组件上下文**，naive-ui 的 `useMessage()` 在
> setup 外调用会在 dev 下直接抛错，所以 composable 内一律不弹提示，全部改为**按返回值由调用方弹**。

## 9. （实施中发现，原文档未列）recalcMarkup 越权删项

**旧版**：`wt`（`:1256-1307`）与 `ft`（`:4170-4204`）**只是遍历已挂项算钱，一个 `splice`/`filter` 都没有**

吊趟 `:5075-5125`。

**新版原先**：`recalcMarkup` 里按「阈值最大者胜」把落选的自动项**从 `l.markup` 直接剔除**。

**后果**：关掉自动加价（`smartdoor_disable_auto_markup`）后，钩子被开关挡住不再增删，
但只要行上任何字段变化触发重算，**用户手动挂的 `超宽N` 也会被悄悄删掉**；原版此时是不动的。

**已改**：`recalcMarkup` 只算钱不增删。顺带删掉随之失去用处的 `parseAutoMarkup` / `isAutoCmMarkup` /
`AUTO_CM_KINDS` / `applies` / `actualOf`。

> 附带确认一件事：`元/公分` 分支**没有阈值守卫**（`:1300` 就是 `r = price*o*数量`）。

> 守卫在钩子里、不在计算里。这也正是「算钱」与「该挂哪些项」必须分开的理由。
