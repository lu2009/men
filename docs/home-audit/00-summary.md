# Home 页保真度审计（2026-09-18）

> 起因：用户问「Home 复刻到什么程度了，有 95% 吗」。答不出来 —— 从没做过系统对照。
> 本文就是那次对照的结果：把旧版 Home 的功能逐条列出，对每条给判定 + 证据。
>
> 三份明细：`01-table.md`（主表/筛选/排序/分页/展开行）、`02-actions.md`（行操作）、
> `03-shell.md`（工具条/财务/看板/通知/两态）。

## 结论：**没有 95%**

| 维度 | ✅ 已做 | ⚠️ 偏离 | ❌ 未做 | ❓ 未确认 | 合计 |
|---|---|---|---|---|---|
| 主表 / 筛选 / 排序 / 分页 / 展开行 | 40 | 42 | 23 | 2 | 107 |
| 行操作 | 13 | 30 | 26 | 1 | 70 |
| 工具条 / 财务 / 看板 / 通知 / 两态 | 18 | 39 | 22 | 3 | 82 |
| **合计** | **71** | **111** | **71** | **6** | **259** |

| 口径 | 比例 |
|---|---|
| **完全一致** | **27.4%** |
| 做了但行为有差异 | 42.9% |
| 未做 | 27.4% |
| 未确认 | 2.3% |
| 「有实现」（已做 + 偏离） | **70.3%** |

⚠️ **口径说明**：分母是「审计条目数」，不是「代码行数」或「用户可见功能数」——
本项目按**细粒度**审（一列一条、一个按钮一条、一条守卫一条），所以数字偏严。
若按「用户能感知的功能块」粗算，覆盖率会高不少。**但这个数字至少是可点着数出来的，不是估的。**

## 一、「未做」的 71 条，按原因分四类

### A. 架构限制 —— 想做也做不了（不是遗漏）

| 项 | 卡在哪 |
|---|---|
| 终端 / 工厂两态（`Yt`）相关的**全部守卫**：删除守卫、保存守卫「已确认的单只能工厂改/删」 | 后端 `users.role` 只有 `admin`/`staff`，**没有终端账号**；终端只读页也没做 |
| 手机端态（`z`）相关：微信分享、复制/分享二选一 | 载体不存在 |
| 云打印 / 导出PDF（旧版用 jsPDF）/ 导出 Excel 族（需 ExcelJS） | 需新依赖或第三方服务 |
| 通知公告（`syncNoticeBoard`） | 无数据源 |

### B. 真功能缺口 —— 能补、该补（**这是最有价值的一批**）

| # | 缺口 | 影响 |
|---|---|---|
| 1 | **列头原生 filters 完全没有** | `n-data-table` 的 `filterOptions`/`filter` 一个没用；含 `__EMPTY__` 空值哨兵、已付/未付列按**金额数字**筛选 |
| 2 | **「查单号」列头 popover** + 单号集列头「清除」 | 旧版唯一的单号筛选入口 |
| 3 | **打单操作列**：进度条下方**没有文字**（旧版有「前段\_」+ 深红加粗末段）、**没有自定义进度段**（localStorage `home_manual_progress_actions`）、**没有 ✓已付徽标**、**格子不可点**（旧版点开「手动更新进度」弹窗） |
| 4 | **「已付清」标记族** | 客户列绿块 `.paid-customer` + 打单操作格 `✓已付`，两处都没有 |
| 5 | **手动更新进度弹窗**整块 | 回执单号 disabled + 操作名称 autocomplete + 日期 + 记录日期 |
| 6 | **审核确认按钮** | 日期格内、未审核时出现 |
| 7 | **删除的密码二次校验** | 旧版 `await y("删除")`；**新版删订单是不设防的** |
| 8 | **改日期会重算截止日期** | 旧版保持「生产周期」不变量；新版改完日期，`due_date` 还是旧的 ⇒ `isDueSoon()` 算出的「临近截止」是错的 |
| 9 | **常驻汇总条** | 旧版**不搜索时也显示**「总计: N 条记录 \| 时间 \| 门数 \| 总价 …」；新版只在有搜索词时显示 |
| 10 | **跨页全选 / 翻页后滚动条复位** | 旧版工具栏那颗全选 checkbox |
| 11 | **展开行两张子表的互斥** | 旧版 `v-show` 切换「平开/吊趟」；新版是「有就都渲染」 |

### C. 观感细节（影响小）

`highlight-current-row`（Naive 无等价物）、行 hover tooltip、行底色 `loaded-row`/`expanded-row`。

### D. 报告交叉发现的**文档错误**（比代码问题更值得修）

1. **`Home.vue:386-387` 的注释说重复单检查「无清晰口径、暂不实现」** ——
   审计发现源码里**口径是明确的**（同客户+同名+同门数+同总价即视为重复，按当前筛选结果实时重算），
   且 CSS 是活的。**注释与源码不符** ⇒ 要么补实现，要么换一个真实的理由。
2. `docs/2026-09-17-home-analysis.md` §4.7 写「`updataProgress`(工序10, 操作名「确认下单」)」——
   实际那条调的是 `Hl("确认下单", [回执单号])`。**分析文档记错**。
3. `02-actions.md` 还挑出旧版自身一个瑕疵：拒绝删除时用的是 `ElMessage.success`（**绿色**）而非 error ——
   补这条守卫时要先定文案色，别照抄。

## 二、「偏离」的 111 条，主要类别

不是每一条都值得修 —— 有些是**有意的、且已论证过**的。主要几类：

| 类别 | 举例 | 性质 |
|---|---|---|
| **打印链路的两层合并** | 旧版「查看回执单」开自己的弹窗、按 `ic` 分支的又开另一个；新版合并成一个 ⇒ 收据入口少一颗（已按用户要求移除重复的） | 有意，已论证 |
| **单元格渲染的等价映射** | Element Plus 组件 → Naive UI；`type="danger"` → `"error"` 之类 | 有意，行为等价 |
| **按钮尺寸/圆角的统一** | 旧版各单据工具条尺寸不一；新版同抽屉内统一 | 有意，观感口径 |
| **多选时截图取全部页** | 旧版只截第一单；新版取全部 | 有意（改进） |
| **明细兜底拉取** | 旧版不补拉未展开订单、打出来是空白；新版统一兜底 | 有意（改进） |

## 三、建议的补做顺序

按「影响 × 可做性」排：

1. **`due_date` 不变量**（第 8 条）—— 这是**算错**，不是少个按钮；会影响「临近截止」的红色告警
2. **列头筛选族**（第 1、2 条）—— 整块缺，且旧版是主要筛选入口
3. **打单操作列的细节**（第 3、4 条）—— 可见度高
4. **删除的密码校验**（第 7 条）—— 安全性相关
5. **手动更新进度弹窗 / 审核确认**（第 5、6 条）—— 两块独立功能
6. **常驻汇总条 / 跨页全选**（第 9、10 条）—— 小，好补
7. **修那三处文档/注释错误**（D 类）—— 零成本，且防止后来人照错的做

## 四、这次审计本身的方法论

- **判定只有四个值**（已做/偏离/未做/未确认），没有中间态；**宁可标「未确认」也不猜**。
- **逐条给证据**：旧版字符偏移 + 新版 `文件:行`。没证据的不写。
- **既有文档只当起点、不当结论** —— 分析文档是分析阶段写的，实现变了它不会跟着变。
  这次就抓到 3 处文档与源码不符。
- **死代码 / 点了没反应的按钮单独记** —— 前几轮靠这条抓到「直接打印回执单其实是云打印」
  「导出PDF 在 ic=13/16 上必定报错」。
